# 명량 해전 제작 흐름 점검 · 2026-09-25

## 실제로 해 본 과정

1. 별도의 빈 시험 브라우저에서 아래 글을 **① 소스**에 붙였습니다.
   > 명량 해전
   > 1597년, 이순신이 이끄는 조선 수군은 명량에서 일본 수군과 싸웠습니다. 이순신은 좁은 울돌목의 지형을 활용했습니다.
2. **한 번에 만들기 → 시작**으로 대본 2장면, 이미지 기획, 업로드 정보, 수업 자료를 만들었습니다. API 키가 없는 간이 모드입니다.
3. 앱이 만든 이미지 주문서 ZIP을 열어 프롬프트를 읽고, Codex 내장 이미지 생성 도구로 실제 그림 2장을 만들었습니다. 생성 요청에는 주문서의 프롬프트를 그대로 사용했습니다.
4. 파일 이름을 주문서대로 `S01-1_2ptk.png`, `S02-1_0k9k.png`로 맞춰 **🎨 이미지 → 만든 이미지 불러오기**로 넣었습니다. 두 그림 모두 제 장면에 들어갔습니다.
5. macOS Yuna 음성으로 만든 한국어 WAV 파일을 각 장면의 **소리 파일** 입력으로 넣었습니다. 선생님 목소리나 마이크 녹음은 아닙니다.
6. **③ 삽화 영상 → 영상 녹화**로 실제 WebM을 내려받았습니다. 1280×720, 앱 타임라인 약 14.74초, 파일 5,263,930바이트입니다.
7. 내려받은 영상을 브라우저에서 다시 열어 5초 지점의 화면을 확인했습니다. 영상의 음성 데이터도 해독되고 무음이 아닌 것을 수치로 확인했습니다. 실행 중 자바스크립트 오류는 없었습니다.
8. 프로젝트 백업과 전체 자료 ZIP을 저장했습니다. 바뀐 대본 편집 화면은 데스크톱과 휴대폰 폭에서 확인했습니다.

## 결과 파일

이 점검을 수행한 컴퓨터의 `output/demo/`에 보관했습니다. 용량이 큰 시연 결과는 Git 커밋에 넣지 않습니다.

- `myeongnyang-demo.webm`: 그림·자막·컴퓨터 음성이 포함된 시연 영상
- `project-backup.json`: **설정 → 백업 불러오기**로 여는 시연 프로젝트
- `all-materials.zip`: 앱에서 만든 대본·PPT·학습지 등
- `image-order.zip`, `prompts.json`, `S01-1_2ptk.png`, `S02-1_0k9k.png`: 주문서, 생성 프롬프트와 실제 그림
- `verification.json`, `recorded-frame.png`, `images-imported.png`, `editor-mobile.png`: 점검 수치와 화면

## 이번에 확인하지 못한 것

- 실제 Claude API 대본 생성과 OpenAI·Gemini 이미지 API 연결은 사용하지 않았습니다.
- 선생님 마이크 녹음, 음성의 청취 품질, PPT를 PowerPoint에서 열기, 편집 프로그램의 MP4 호환성은 미확인입니다.
- 생성 그림의 배·복식·깃발·지형은 고증 검수를 마치지 않았습니다. 영상 제작 흐름을 확인하는 시연용이며, 수업이나 공개 영상에 쓰기 전 역사 내용과 그림을 검토해야 합니다.
- 기본 Playwright 지정 브라우저 설치는 이전 점검에서 멈췄으므로, 설치된 Chromium headless shell(build 1223)을 지정했습니다.

## 점검 중 해결한 환경 문제

- 샌드박스 안에서 macOS 음성 생성 명령이 길이 0인 파일을 만들었습니다. 시스템 음성 서비스에 접근 가능한 실행으로 다시 만들자 정상 음성이 저장됐습니다. 앱의 파일 입력 문제는 아니었습니다.
- 끌기 자동 시험은 대상 장면이 화면 밖에 있으면 끌기 이벤트를 만들지 못했습니다. 두 장면이 보이는 화면 크기에서 실제 마우스 끌기와 키보드 ↑↓ 조작을 확인했습니다.
